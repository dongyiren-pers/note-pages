# 第5章 详细设计

详细设计的目的：确定具体编程序方案；

软件详细设计的 主要任务是确定每个模块的算法和使用的数据结构。

  • 确定每个模块的算法；
  • 确定每一个模块的数据组织；
  • 为每个模块设计一组测试用例；
  • 编写详细设计说明书。

# 5.1 结构化程序设计

结构化程序设计主张使用 三种基本结构（顺序结构、选择结构和循环结构） 来构建程序，并通过 自顶向下、逐步求精 的方式进行编程。此外，结构化程序设计还强调 模块化，即保持模块的 单入口、单出口，以提高程序的可读性和可维护性。

# 5.2 人机界面设计

人机界面设计中的四个设计问题：

  • 系统响应时间；
  • 用户帮助设施；
  • 出错信息处理；
  • 命令交互。

# 5.3 过程设计的工具

# 程序流程图

程序流程图又称为程序框图，它是历史最悠久、使用最广泛的描述过程设计的方法。

符号：

# 盒图（N-S图）

符号：

程序流程图用箭头代表 控制流，可以随意转移控制。

# PAD 图

PAD 是问题分析图（problem analysis diagram）的英文缩写。

符号：

PAD 图中 竖线的总条数就是程序的层次数。

# 判定表

判定表右半部的每一列实质上是一条规则，规定了与特定的条件组合相对应的动作。

# 判定树

判定树能清晰地表达复杂的条件组合与所对应的操作之间的关系，易于理解和使用。
